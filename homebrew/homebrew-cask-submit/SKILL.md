# Homebrew cask submit

Cookbook, Acceptable Casks, and the checkout `CONTRIBUTING.md` already apply. Stop when a check here fails.

**URL.** After stripping the query, 401/403 or `X-Amz-Expires` / `Expires` / `token=` is unusable. URL version = `CFBundleShortVersionString`, including build number and hash. Token is free only if `gh api repos/Homebrew/homebrew-cask/contents/Casks/<letter>/<token>.rb` is 404; then read closed unmerged PRs. The token is also taken by homebrew-core: `gh api repos/Homebrew/homebrew-core/contents/Formula/<letter>/<token>.rb` — a formula hit means the token becomes `<token>-app` (`atlas-app`, `codex-app`, `cline-app` precedents). Check both namespaces before writing the cask or branch. `whois` the homepage: ≥30 days. That audit runs only on the official tap. Forges are exempt; switching `homepage` to one waits for the user. Notability is the GitHub repo inside `url` — under 30 forks, 30 watchers, and 75 stars, use the vendor endpoint (`sha256 :no_check`; a 302 to GitHub is fine). A fake version that still returns the latest file means the path ignores `#{version}`. `*-latest` → `sha256 :no_check`. `version :latest` excludes `auto_updates`. Omit `verified:`. Find the feed in `SUFeedURL`, `app.asar`, or the download-button JS, on the vendor host.

**Arch.** `lipo -archs` `Contents/MacOS/` for every build you declare. The filename, and any fat helper or dylib, is not the app's arch. A one-arch feed gets `depends_on arch:` for that arch. Mount with `diskutil image attach --readOnly --mountOptions nobrowse`; unmount with `diskutil unmount` on the volume. On macOS 26+, `hdiutil attach` aborting in autofsck is what brew calls `Download failed`.

**Pair.** Different bundle id, homepage, accounts, and support dir: two casks, two PRs, each from upstream `main`, neither an ancestor of the other. Bare token is the default edition; the suffix is the region. Say why, and link the sibling, in the first paragraph. Same `.app`: `app "Name.app", target: "Name Region.app"`. `conflicts_with` waits until that token is in the official tap.

**livecheck.** Both archs: `#{arch}` in the feed URL and the filename regex, regex passed in as `do |json, regex|`. A version field is read directly (`json["currentRelease"]`). One arch: hardcode it. Sparkle with distinct `shortVersionString` + `version` collapses to the build (`1.1` + `1.1.143` → `1.1.143`); a filename like `App-1.1-143.zip` is templated `#{version.major_minor}-#{version.patch}`. A vendor shipping builds daily re-fails CI's version audit before merge — re-read the appcast before each push, and on drift bump `version` + `sha256` from the newest enclosure after re-checking arch and bundle id, as an incremental commit.

**zap.** Paths created by launching that build: `open` it, wait out launch and quit, then `find ~/Library -maxdepth 3 -name "*<bundle-id>*"` — ship exactly those. Entitlements only suggest candidates; an unsandboxed app never creates `Containers` or `Group Containers` dirs, app-group or not, and `.binarycookies` / `Saved Application State` / `WebKit` stay out until the launch shows them. CI runs `brew cask-ci check`, which launches the app and diffs a machine snapshot (installed apps, pkgs, kexts, launch jobs) against the stanza: a missing path fails review, a guessed path can delete unrelated data. On a shared log or crashpad dir, the glob matches this bundle id only (`com.vendor.app-*.log` vs `com.vendor.app.region*.log`). A dir both editions write goes in both. `uninstall quit:` is the bundle id. Servers and updaters register launchd jobs: often no plist on disk (bootstrap-registered) and a per-machine hash suffix (`com.vendor.app.server.<64-hex>`), so after the launch test run `launchctl list | grep -i <vendor>` and ship `uninstall launchctl: "com.vendor.app.server.*"` — a glob, since the hash differs per machine — and leave it out of `zap trash:`. The CI failure names the offending label verbatim: "Some launch jobs were not unloaded, add them to uninstall launchctl:".

**Test.** `brew audit --cask --online --new <user>/<tap>/<token>` — auditing a path is disabled, and the three flags stay together. Tap a repo that contains only this cask. `brew untap --force` on a second full homebrew-cask checkout uninstalls the user's casks. `brew info` `From:` can be a custom remote. Run `brew trust <user>/<tap>` before the first audit — an untrusted tap refuses to load the cask and the run is wasted. `brew trust` has no delete verb: remove entries by stripping `<user>/` entries from `~/.homebrew/trust.json` (keys `trustedtaps`, `trustedcasks`, `trustedformulae`, `trustedcommands`), then `brew untap <user>/<tap>`. CI failure diagnosis while the run is in flight: `gh api repos/Homebrew/homebrew-cask/actions/runs/<id>/jobs --jq '.jobs[] | select(.conclusion == "failure") | {name, steps: [.steps[] | select(.conclusion == "failure") | .name]}'` — `gh run view --log-failed` refuses until the run completes. Install with `HOMEBREW_NO_INSTALL_FROM_API=1` and `--appdir=/tmp/cask-test`. Run `brew autoremove --dry-run` before uninstall. A `pkill -f` pattern must not appear in that same command.

**PR.** Show the body before `gh pr create` unless the user already said to open it. Squash to one commit per cask, per that checkout's CONTRIBUTING. Checkbox lines stay byte-for-byte, including `<cask>`. Put the reason above the template. The title is the commit subject verbatim: `<token> <version>`, `(new cask)` appended on a new cask, `<token>: <description>` on a fix — review renames unmarked new-cask titles by hand (`bevanjkay`, `SMillerDev` precedents), so set it right at creation. This prints `true`:

```sh
gh api repos/Homebrew/.github/contents/.github/scripts/check_template.rb --jq .content | base64 --decode > /tmp/check_template.rb
ruby /tmp/check_template.rb pull-request /tmp/pr_body.md .github/PULL_REQUEST_TEMPLATE.md "<commit-subject>" Homebrew/homebrew-cask
```

Name the model on every PR it drafted. A non-maintainer has one open AI-assisted PR; do not relabel a drafted PR as unused AI. The user writes review replies. A template-bot close is fixed by editing the body.
